# 政策维护手册（Policy Maintenance Runbook）

> 面向维护者：当税收政策发生新增、延续、调整或停止执行时，按本手册更新系统，确保
> **算税数字、申报表栏次、政策依据（文号/条款/生效日/衔接关系）三者一致**。
>
> 核心原则：**历史版本不可篡改，只追加新版本；依据必须能追溯到官方原文。**

---

## 0. 为什么需要版本化（真实案例）

2023—2025 年，小规模纳税人增值税免征依据是《财政部 税务总局公告 2023 年第 19 号》；
2026-01-01《中华人民共和国增值税法》施行后，该公告依据 **2026 年第 10 号公告第六条自
2026-01-01 起停止执行**，优惠由《关于增值税法施行后增值税优惠政策衔接事项的公告》
（财政部 税务总局公告 **2026 年第 10 号**）承接：

- 第一条：起征点 月 10 万元 / 季 30 万元 / 按次（日）1,000 元，2026-01-01 至 2027-12-31；
- 第三条第三项第 6 目：小规模纳税人**除销售、出租不动产或者转让土地使用权之外**的应税交易，
  依 3% 征收率减按 1% 征收，执行至 2027-12-31；
- 第二条第二项第 2 目：技术转让、技术开发及相关的技术咨询、技术服务免征增值税（需认定备查）。

如果只在代码里改数字、不改依据，就会出现“金额算对、依据写错”的硬伤——税务沟通和审计时
无法自证。本系统用「期间 → 政策版本 → 依据列表」的映射避免这一点。

## 1. 政策数据在哪里

| 位置 | 内容 | 维护方式 |
|---|---|---|
| `engine/policy_params.py` → `POLICY_VERSIONS` | 政策版本：生效区间、参数覆盖、依据列表（标题/文号/条款/生效日/失效日/链接/备注）、停用文件 | **主要修改点** |
| `config.py` → `POLICY` | 各版本共用的基础参数（1%、30 万、六税两费减半、小微 5%、研发 100% 等） | 政策参数变化时改 |
| `knowledge/policy_files/**/*.md` | 面向用户/Agent 的政策解读（frontmatter：`effective_date`、`expiry_date`、`source`、`last_verified`） | 同步更新正文与 frontmatter |
| `filing/*.py` | 申报表栏次与填报口径 | 栏次/表样变化时改 |
| `tests/test_engine.py::TestPolicyParams`、`tests/test_integration.py` | 期间映射与依据引用回归测试 | 新增版本必须补测试 |

版本的字段要求：

```python
{
    "id": "2026-2027",                     # 唯一、稳定，不随文案变化
    "label": "2026—2027 年（《增值税法》施行后，依据公告2026年第10号）",
    "effective_from": "2026-01-01",
    "effective_to": "2027-12-31",
    "region": "全国",                       # 未来可扩展地区差异
    "params": { ... },                      # 仅覆盖与基础参数不同的键
    "sources": [                            # 本期间适用的依据（按税种标注 applies_to）
        # {title, source, effective_date, expiry_date, applies_to, url, note}
    ],
    "notes": [ ... ],                       # 衔接、排除、按次起征点等口径说明
    "supersedes": ["2023-2025"],
    "superseded_documents": ["财政部 税务总局公告2023年第19号（自2026-01-01起停止执行）"],
}
```

## 2. 新增/调整政策的标准流程

1. **找原文**：优先财政部（`szs.mof.gov.cn`）、税务总局（`chinatax.gov.cn`）官网公告；
   核对**文号、发布日期、施行日期、有效期、条款序号**。二手转载只用于定位，不用于定稿。
2. **判断影响面**：只影响税率/限额？还是影响申报表栏次、减免性质、备案要求、附加税费联动？
   是否属于“停止执行旧文件”的衔接公告（注意公告最后一条的“停止执行”条款）。
3. **新建版本**：复制上一版本，修改 `id`、`label`、`effective_from/to`、`params`、`sources`、
   `notes`、`superseded_documents`。**不要改已发布的历史版本**，否则历史期间算税会漂移。
4. **同步知识库**：更新对应 `knowledge/policy_files/**/*.md` 的 frontmatter
   （`effective_date`、`expiry_date`、`source`、`last_verified` 改为核验日）与正文，
   并在文末“政策沿革”表补一行。
5. **补回归测试**：至少覆盖
   - 新旧期间的边界（如 2025Q4 → 旧版本、2026Q1 → 新版本）；
   - `policy_sources` / `vat_policy_source` 引用正确文号；
   - `superseded_documents` 显式列出停止执行的旧文件；
   - 关键算税结果与旧版本对比（金额口径是否应按政策变化）。
6. **全量验证**：`pytest tests/ -q` 全绿；用 CLI 抽查两个期间的算税与申报包：
   ```bash
   .venv/bin/python main.py calc-vat --total 280000 --special 101000 --period 2026Q2
   .venv/bin/python main.py file --period 2026Q2 --out /tmp/check
   ```
7. **更新记录**：README 政策表、本手册的“变更日志”、知识库 `update_checker` 的 `last_verified`。

## 3. 红线与常见坑

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 只改数字不改依据 | 依据引用已停止执行文件，税务沟通无法自证 | 依据与参数同版本维护 |
| 直接修改历史版本 | 历史期间算税结果漂移、申报记录无法复现 | 追加新版本，保留历史 |
| 忽略“停止执行”条款 | 继续引用 2023 年第 19 号等已停止文件 | 读公告最后一条；写 `superseded_documents` |
| 忽略适用范围排除 | 对不动产等业务错误套用 1% | 在 `params` 写 `vat_reduction_exclusions` 并提示 |
| 忽略地区差异 | 城建税 7%/5%/1%、地方附加口径不同 | 未来用 `region` 维度扩展；当前云南按 7% |
| 附加税费未联动 | 主税变、附加税未变 | 附加税费由增值税应纳额 × 12% × 六税两费减半计算，检查联动 |
| 知识库与代码不同步 | Agent 回答与算税依据矛盾 | 同一 PR 同时改代码、知识库、测试 |
| 忘了“按次/按季/按月”口径 | 起征点误用 | 保留 `vat_exemption_limit_month/quarter` 与按次阈值 |

## 4. 上线前检查清单

- [ ] 官方原文已核对（文号、施行日、有效期、条款）
- [ ] 新版本 `POLICY_VERSIONS` 已追加，历史版本未改
- [ ] `superseded_documents` 已列出停止执行文件
- [ ] `get_params(period)` 边界测试通过（旧/新期间各一）
- [ ] 算税结果 `vat_policy_source` 指向正确文号
- [ ] 申报表 bundle 的 `policy_basis_text` 与填报指引一致
- [ ] 知识库 frontmatter 与正文已更新，`last_verified` 为核验日
- [ ] Agent System Prompt / 工具输出 / 本地回复引用动态依据（无硬编码文号）
- [ ] `pytest tests/` 全绿
- [ ] README 政策表与变更日志已更新
